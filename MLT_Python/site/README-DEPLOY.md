# Deploying this site

The site itself is fully static (no build step) — lecture/lab content is pre-generated into
`content.js` / `labs_content.js`. As of the "Ask MLT AI" chatbot feature, there is also one
serverless function (`netlify/functions/chat.js`) that needs an environment variable and a
Functions-capable deploy method (see below — plain drag & drop does **not** support it).

## Option A — Drag & drop (fastest, but the chatbot won't work)

1. Go to https://app.netlify.com/drop
2. Drag the entire `site` folder onto the page.
3. Netlify gives you a live URL in a few seconds (e.g. `random-name-123.netlify.app`).
4. You can rename the site later from **Site settings → Change site name**.

⚠️ Drag & drop only publishes static files — it does **not** deploy the `netlify/functions/`
folder, so the "Ask MLT AI" chat page will load but every message will fail. Use Option B or C
if you want the chatbot working.

## Option B — Netlify CLI (recommended — supports the chatbot)

```bash
npm install -g netlify-cli
netlify login                 # first time only
cd site
netlify init                  # first time only, links this folder to a Netlify site
netlify deploy --prod
```

Then set the required environment variable (Site settings → Environment variables, or via CLI):

```bash
netlify env:set OPENAI_API_KEY "sk-..."
# optional, defaults to "gpt-4.1":
netlify env:set OPENAI_MODEL "gpt-4.1"
```

Redeploy (`netlify deploy --prod`) after setting env vars for the first time.

## Option C — Connect a Git repo (auto-deploys on every push, supports the chatbot)

1. Push this project to GitHub/GitLab/Bitbucket.
2. In Netlify: **Add new site → Import an existing project** → pick the repo.
3. Set **Base directory** to `site`, **Publish directory** to `site` (or `.` if the repo root
   only contains the `site` folder), and leave **Build command** empty — there's nothing to build.
4. In **Site settings → Environment variables**, add `OPENAI_API_KEY` (and optionally
   `OPENAI_MODEL`). Never commit the key itself to the repo.

## Updating the content later

If you edit or add lecture `.md` files or lab assignment scripts, regenerate the pre-built data
files before redeploying (from the project root, one directory above `site/`):

```bash
python3 -m venv .venv        # first time only
.venv/bin/pip install markdown2
.venv/bin/python3 build_site.py       # regenerates site/content.js
.venv/bin/python3 build_labs.py       # regenerates site/labs_content.js (if labs changed)
python3 build_chat_data.py            # regenerates the chatbot's data file (stdlib only, no venv needed)
```

(Ask Claude to do this after adding new lecture notes or lab assignments — it already knows this
sequence from `CLAUDE.md`.)

## What's in this folder

- `index.html` — the app shell.
- `style.css` — all styling (light/dark theme, responsive layout, chat UI).
- `app.js` — client-side router, sidebar, search, tabs, and the "Ask MLT AI" chat page — no
  framework, no build step.
- `content.js` — all lectures' notes, pre-rendered from Markdown to HTML at build time.
- `labs_content.js` — all lab assignments, pre-parsed from the `.py` scripts.
- `diagrams.js` — hand-drawn inline SVG recreations of specific slide diagrams.
- `netlify.toml` — cache headers, the Functions directory, and the `/api/chat` redirect.
- `netlify/functions/chat.js` — the "Ask MLT AI" chatbot backend (Netlify Function). Holds the
  OpenAI API key server-side, calls OpenAI's Responses API with a `web_search` tool for live
  research plus two custom tools (`get_topic`, `get_lab_section`) that fetch exact lecture/lab
  text on demand.
- `netlify/functions/chat-data.json` — a lean, plain-text export of `content.js`/`labs_content.js`
  that the chat backend loads at cold start. Regenerated by `build_chat_data.py`, never edited by
  hand.
